# Reproducing the benchmark locally

For the manuscript's full headline-result-to-command mapping, use [`reproduce-manuscript-headlines.md`](reproduce-manuscript-headlines.md). This page contains the acquisition detail and input restrictions.

The source code is published at <https://github.com/web-designer-coder/india-heatwave-benchmark> under the MIT license. This repository release has no DOI; cite the software using the included `CITATION.cff`.

## Data and outputs

- Target: daily 1-degree IMD Tmax. Follow IMD's current product access route and preserve its citation and applicable use conditions. The annual binary files are intentionally excluded from any prospective code archive.
- Predictors: hourly ERA5 fields from the Earthmover public Icechunk mirror, pinned to snapshot `TZ2KX6A24CJ5DG17T7MG` (CC BY 4.0 as recorded in the acquisition manifest).
- The exact local source, snapshot, grid-point selection, checksums, and date ranges are recorded in `data/processed/acquisition_manifest.json`, `data/raw/imd/download_manifest.json`, and the ERA5 source manifests. Check these files against the actual local checkout before reproducing.
- The core input files and generated outputs under `data/interim/` and `reports/` are not automatically included in a code archive. Re-download data using documented commands and the provider's current access route.

## Environment and commands

Use the locked `uv.lock` environment. From the project root, install the core dependencies with `uv sync --locked`; for ERA5 Icechunk access, use `uv sync --locked --extra era5-cloud`. Run the benchmark with `uv run --locked python scripts/run_benchmark.py`. Run the onset-transition analysis with `uv run --locked python scripts/run_transition_benchmark.py`. Rebuild the frozen onset artifact with `uv run --locked --extra era5-cloud python scripts/freeze_onset_model.py`.

The analysis configuration and random seed are in `configs/benchmark.json`. The fit cap, validation-derived calibration/threshold procedures, splits, and label rules are encoded in `src/heatwave_benchmark/`. The frozen onset parameters, features, calibration period, threshold, and artifact digest are in `docs/frozen_onset_protocol_2026-10-27.md`. Rebuild the grouped Brier decomposition with `uv run --locked python scripts/run_brier_decomposition.py`; it writes `reports/generated_era5/brier_decomposition_100bins.csv`. Rebuild exploratory paired year/fold intervals for the onset redesign with `uv run --locked python scripts/run_onset_redesign_paired_bootstrap.py`; it writes `reports/onset_model_era5/onset_paired_bootstrap_intervals.csv`.

Rebuild the alternative relative-threshold label sensitivity with `uv run --locked python scripts/percentile_label_sensitivity.py`. It uses local daily Tmax percentiles from a centered 31-day window and the fixed 1981--2010 reference period, then retains runs lasting at least three consecutive days. It writes target-overlap and full benchmark-suite metrics to `reports/percentile_label_sensitivity/label_overlap_metrics.json`. This is a separate research target based on a published India heatwave definition, not an official IMD declaration. Models are refit against this alternative target, but evaluation uses the already inspected 2014--2025 period and is exploratory rather than confirmatory.


Refit the HGB model and compare it with climatology and persistence under the 1981--2000, primary 1981--2010, and 1991--2010 target normals using `uv run --locked python scripts/evaluate_label_normal_hgb_sensitivity.py`. The script recalculates target labels, fits/calibrates on the designated training/validation periods, and writes metrics and run metadata to `reports/generated_era5/label_normal_hgb_sensitivity/`. The 2014--2025 test period had already been inspected, so these comparisons are exploratory.
## Frozen 2026 temporal evaluation

The 2026 temporal test was run after freezing the HGB artifact, feature list, training-fitted anomaly normals, calibrator, and threshold. IMD's real-time 1-degree Tmax grids for 1 March--30 June 2026 were acquired with `uv run --locked python scripts/download_imd_realtime_2026.py`; the daily file hashes are in `data/raw/imd_realtime_2026/download_manifest.json`. The matching 275-cell ERA5 window (22 February--30 June 2026) was acquired from the same fixed Icechunk snapshot using `uv run --locked --extra era5-cloud python scripts/acquire_independent_era5_2026.py`; hashes are in its per-cell download manifest. Run the frozen HGB scoring, development-fitted climatology/persistence comparisons, and paired seven-day date-block intervals with `uv run --locked --extra era5-cloud python scripts/evaluate_frozen_onset_2026.py`. The climatology comparator uses only 1981--2007 training and 2008--2013 calibration/threshold data. Render the paper's precision-recall figure using `uv run --locked python scripts/render_independent_onset_2026_figure.py`.

The output is a new out-of-time period from the same IMD and ERA5 source families, not independent-source validation. ERA5 predictors are retrospective; the test is not operational forecast verification. Its metrics and limits are documented in `docs/independent_evaluation_status_2026-10-27.md`. IMD inputs and row-level derived predictions are retained locally and are not redistributed.

## Frozen 2026 external-product evaluation

Acquire NOAA CPC daily Tmax and NMAX values for 22 February--30 June 2026 with `uv run --locked python scripts/acquire_cpc_tmax_2026.py`; the script uses verified HTTP byte ranges from the CPC archive and records SHA-256 checksums in `data/raw/cpc_tmax_2026/acquisition_manifest.json`. Then run `uv run --locked python scripts/evaluate_frozen_onset_cpc_2026.py`. It aggregates four 0.5-degree CPC grid centers to each 1-degree study cell, requiring at least three finite values, applies the existing IMD-aligned label thresholds with the fixed IMD 1981--2010 cell normals, and scores the frozen 2026 probabilities and thresholds. It does not fit or retune the model. CPC constructs its product from GTS daily reports; those may overlap IMD source reports, so this is a separate product analysis and not guaranteed independent-source station validation. ERA5 predictors remain retrospective. Results and paired 7-day date-block intervals are written to `reports/independent_cpc_2026/`.

The post hoc CPC report-support sensitivity can be reproduced with `uv run --locked python scripts/summarize_cpc_reporting_support_2026.py`. It restricts the already frozen predictions to rows with positive CPC NMAX support on both the issue and verifying dates; it does not refit or retune models. Its output is `reports/independent_cpc_2026/cpc_report_supported_sensitivity_2026.json`. Because this subset is selected using product metadata and covers one season, treat it as descriptive sensitivity analysis only.

## Reproduction limits

A clean locked-environment comparison of primary benchmark metrics and predictions passed using cached inputs; the detailed audit is retained in the research workspace and is not part of this code release. The full temporal and five-fold spatial benchmark was recomputed from cached IMD and ERA5 NetCDF inputs. A separate fresh IMD acquisition audit redownloaded all 45 annual 1981--2025 files and matched the recorded checksums; its detailed report is retained locally and excluded from this release. A fresh full-period ERA5 acquisition and end-to-end model rerun from newly acquired ERA5 inputs were not performed. To perform that source audit, run `uv run --locked --extra era5-cloud python scripts/audit_fresh_full_era5.py`; it downloads to a separate raw-data directory and compares the acquired fields with the analysis input. Raw IMD, ERA5, CPC, NASA POWER, and GHCN-Daily data are not redistributed. Obtain them through the documented provider access routes and follow applicable terms; do not infer redistribution permission from download availability.

A source-only ZIP can be rebuilt with `uv run --locked python scripts/build_source_archive.py`. It includes the code, locked environment, license, citation metadata, and documentation; its allowlist excludes acquired data and generated reports. The ZIP is a local archive artifact; this script does not publish it or create a DOI.

## GHCN-Daily station-data screen (not model validation)

The GHCN-Daily station data acquisition is recorded by `scripts/acquire_ghcnd_india_station_data.py`; it retrieves the NCEI inventory and India station files. The source subset and file checksums are stored in `reports/independent_ghcnd_2026/`. Run `uv run --locked python scripts/audit_ghcnd_independent_2026.py` to reproduce the coverage and source-flag audit. The audit found that every one of the 5,229 quality-accepted March--June 2026 records has TMAX measurement flag H (highest hourly temperature), rather than conventional daily Tmax. These records are therefore excluded from target construction and model scoring. Do not run or cite `scripts/evaluate_frozen_onset_ghcnd.py` as validation; its outputs are exploratory hourly-proxy analyses and are not compatible with the paper's daily-Tmax target. Raw station files are excluded from the local source archive.

## NASA POWER/MERRA-2 product-level target check (exploratory)

Run `uv run --locked python scripts/evaluate_frozen_onset_power_2026.py` to reacquire NASA POWER `T2M_MAX` at the frozen 275 study locations for 1 March--1 July 2026, reconstruct target labels using 1981--2010 POWER-specific Tmax normals and the existing IMD-aligned grid-cell thresholds, and score the unchanged frozen onset probabilities from `reports/independent_onset_2026/frozen_model_all_grid_scores_2026.csv.gz`. The script stores the raw point responses and checksums under `data/raw/nasa_power_2026_product_check/`, writes the row-level eligible comparison to `reports/independent_power_2026/frozen_onset_power_predictions_2026.csv.gz`, and writes metrics plus paired 7-day block-bootstrap intervals to `reports/independent_power_2026/frozen_onset_power_metrics_2026.json`. It does not refit the model, calibrator, threshold, or climatology. This analysis was selected after inspection of the other 2026 evaluation outputs and must remain labelled exploratory. POWER is a gridded analysis product, not independent station observations; its LST day boundary differs from the IMD day, and possible overlap in assimilated observations with other products cannot be excluded. It does not establish operational forecast skill.

## Additional reproducible audits

- Reproduce annual 2014--2025 temporal-test metrics from saved predictions with `uv run --locked python scripts/summarize_yearwise_temporal_test.py`; output is `reports/generated_era5/yearwise_temporal_test_metrics.csv`.
- Check bibliography DOI resolution and title/year metadata with `uv run --locked python scripts/audit_bibliography_crossref.py`. It checks Crossref and falls back to DataCite when needed; the 28 October 2026 audit resolved all 29 cited DOI entries with no title or year mismatches. The snapshot is `reports/bibliography_doi_audit_2026-10-28.json`. References without a DOI are outside this automated check and still need their source pages or publications checked manually.
- Repeat the OpenAlex search with `uv run --locked python scripts/search_openalex_heatwave.py`; it writes a dated record under `reports/`. Summarize India-relevant returned titles with `uv run --locked python scripts/summarize_openalex_candidates.py`. Repeat the Crossref metadata search with `uv run --locked python scripts/document_novelty_search.py`; it writes a JSON file named for the current search date. The captured snapshots are `reports/openalex_heatwave_search_2026-10-25.json` and `docs/novelty_search_crossref_2026-10-27.json`. See `docs/novelty_search_log_2026-10-27.md` for exact queries, publisher searching, manual screening, and search limitations. These searches are focused novelty checks, not a systematic review; Scopus and Web of Science searches remain outstanding.
