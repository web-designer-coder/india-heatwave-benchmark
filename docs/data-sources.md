# Data sources and acquisition notes

Last checked: 2026-10-28.

## IMD daily maximum temperature

- Official archive page: <https://www.imdpune.gov.in/cmpg/Griddata/Max_1_Bin.html>
- Download endpoint used by the page: <https://www.imdpune.gov.in/cmpg/Griddata/maxtemp.php>, with the selected year submitted as the `maxtemp` form field.
- Grid: 31 latitude by 31 longitude points at 1-degree spacing; latitude centers 7.5N to 37.5N and longitude centers 67.5E to 97.5E. Values are little-endian float32 degrees Celsius; `99.9` means undefined.
- The page text documents 1951-2024. Its year selector and live endpoint also supplied a structurally valid 2025 file during the 2026-10-24 check. The acquisition manifest records the precise files downloaded and validated.
- IMD notes that the 2008-onward product is based on fewer stations (around 180) than earlier years. The evaluation therefore reports year-level performance and treats 2008 as a potential observation-coverage break.
- Requested citation: Srivastava, Rajeevan, and Kshirsagar (2009), "Development of High Resolution Daily Gridded Temperature Data Set (1969-2005) for the Indian Region," *Atmospheric Science Letters*, DOI <https://doi.org/10.1002/asl.232>.

## NASA POWER daily meteorology (exploratory predictor pilot)

- API: <https://power.larc.nasa.gov/api/temporal/daily/point>; official daily API documentation: <https://power.larc.nasa.gov/docs/services/api/temporal/daily/>.
- The archived point responses identify `MERRA2` and `POWER` in their source tags and API version `v2.10.1`. NASA documents its meteorological inputs as GMAO MERRA-2 at a native 0.5° latitude by 0.625° longitude grid, with daily data available from 1981 and daily aggregates derived from hourly inputs. Data from each point request are requested at the 275 observed IMD cell centers; actual POWER response coordinates are retained rather than treating them as 1° measurements.
- Predictors: daily T2M, T2M_MAX, T2M_MIN, RH2M, WS2M, PS, and PRECTOTCORR. Units are retained from each response. NASA POWER daily requests default to local solar time; these archived responses use `LST`. This is not identical to Indian Standard Time or the IMD daily observation window, so day-boundary differences are a limitation and issue dates should not be read as an operational issuance schedule.
- The response metadata, API version, source tags, coordinates, checksums, and dates are stored in raw caches and the acquisition manifest. NASA's referencing guide requests naming the service, version, and access date in publications, and asks users to notify the POWER team when a paper is published: <https://power.larc.nasa.gov/docs/referencing/>. Include the data version and access date from the manifest in the final paper.
- NASA documents the daily API as analysis-ready meteorological data and warns that source data are provided at native resolution. The predictor archive is retrospective, so this project evaluates retrospective prediction skill rather than operational forecasts.
- NASA POWER was used in a separate exploratory predictor pilot and in a post hoc 2026 target-product check. NASA's source documentation describes its long-term meteorological fields as MERRA-2 and its low-latency extension as GEOS-IT; retain each acquired API response's source tags rather than assuming which product supplied every date. The 2026 target check and its limitations are documented in `docs/independent_evaluation_status_2026-10-27.md`. POWER is not the predictor source for the current primary manuscript results and is not independent station truth.

## ERA5 hourly meteorology (completed primary predictor source)

- ERA5 is the Copernicus Climate Change Service's hourly global reanalysis on a 0.25-degree grid, documented at <https://cds.climate.copernicus.eu/datasets/reanalysis-era5-single-levels>. The project uses the public AWS mirror registered at <https://registry.opendata.aws/earthmover-era5/>. It provides anonymous S3 access to Icechunk/Zarr v3 data; the temporal layout is optimized for time-series extraction and the current registered archive covers the full 1981-2025 study period. The mirror's registry states that its stored values are lossless and bit-for-bit identical to the source ERA5 NetCDF fields.
- The downloader opens `earthmover-icechunk-era5/icechunkV2`, group `single/temporal`, and reads `t2m`, `d2m`, `u10`, `v10`, `sp`, and `tp`. The resolved Icechunk snapshot ID is saved once in `source_manifest.json` and reused on resume, so all annual windows come from one immutable archive state. Coordinates are selected at the nearest 0.25-degree ERA5 grid cell to each of the 275 observed IMD 1-degree cell centers.
- For each year, the downloader extracts UTC hourly records from 19:00 UTC on February 21 through 18:00 UTC on June 30. Converting these timestamps to `Asia/Kolkata` yields complete February 22-June 30 local dates, with 24 hourly records each. It derives mean/minimum/maximum 2-m temperature in °C; hourly relative humidity from temperature and dewpoint using the Magnus approximation, then averages RH; computes scalar 10-m wind speed from `u10`/`v10` and averages it in m/s; averages surface pressure in hPa; and sums hourly `tp` accumulation in mm. The mirror describes `tp` as a one-hour accumulation ending at its valid time. Unit conversion, daily aggregation, coordinate mapping, snapshot, raw window checksums, and cache checksums are recorded in reproducible manifests.
- Only February 22 through June 30 is extracted per year, covering the March-June issue dates and seven preceding calendar days used by the feature builder. Requested points are grouped by the source's native 12-by-12 spatial chunks and read concurrently; `--era5-workers` controls concurrency. Each validated cell cache is written atomically, so reruns skip completed cells and continue missing or invalid cells. The final per-cell cache has a full calendar index, with null predictors outside the extracted windows. The model frame still uses only the declared issue months and exact calendar-day lags.
- The optional alternate delivery route is Open-Meteo's Historical Weather API (<https://open-meteo.com/en/docs/historical-weather-api>), selected with `--era5-provider open-meteo`. Its quota, current pricing/terms, and daily aggregation behavior differ from the direct cloud mirror and must be documented if that route is used. API terms: <https://open-meteo.com/en/terms> and <https://open-meteo.com/en/pricing>.
- The current primary manuscript results use ERA5 predictors. The complete local acquisition manifest contains 275 grid cells spanning 1981--2025, all marked `downloaded`; annual cell-window manifests and the source snapshot are retained under `data/raw/era5_icechunk/`. The assembled hourly-derived daily predictor dataset is `data/interim/era5_1981_2025.nc`, and the primary feature table is `data/interim/benchmark_features_era5.csv.gz`. Primary benchmark outputs are in `reports/generated_era5/`. The separate 2026 frozen evaluation uses a matching 275-cell window from the same pinned snapshot, with its own manifest under `data/raw/era5_onset_independent_2026/`.
- A fresh-source audit compared one grid cell for 2025 (129 daily values) against its cached record and found every variable within an absolute difference of 1e-4. This is a sample check, not a fresh reacquisition of all 275 cells and 45 years. The full historical raw inputs have not been reacquired from scratch for an end-to-end reproduction.
- Cite the Earthmover public mirror registry, the underlying ERA5 dataset, the immutable snapshot ID, and access date. The Earthmover registry specifies CC BY 4.0 and provides a recommended citation. The current manuscript includes the Copernicus modified-product attribution and disclaimer required by the applicable license; verify the current terms again at submission. The license page is <https://cds.climate.copernicus.eu/licences/licence-to-use-copernicus-products>.

## Terrain mask

Terrain categories use `region_mask_100.npy`, distributed with `imdlib` 0.4.0 and licensed under MIT. The CSV included in `src/heatwave_benchmark/` is transposed from the upstream longitude/latitude storage order into the package's latitude/longitude grid. Codes are -1 outside/ocean, 0 plains, 1 hilly, and 2 coastal. This is an auxiliary label input, not a substitute for IMD station-based subdivision declarations.

The analysis domain is filtered to IMD grid centers inside the Natural Earth Admin 0 India polygon, 1:10m scale, version 5.1.1. Archive: <https://naciscdn.org/naturalearth/10m/cultural/ne_10m_admin_0_countries.zip>. The downloaded source archive SHA-256 is `ce1ac7036499a0edd641fbc093cd209a98f96a49d2eca8480aaacad35138a7f6`. Natural Earth data are public domain; the upstream terms are at <https://www.naturalearthdata.com/about/terms-of-use/>. The included GeoJSON records its source, and the selection is by grid-center containment rather than fractional area overlap. Border cells whose centers fall outside the polygon are excluded.

## Spatial groups

Spatial holdouts use fixed 5-degree latitude/longitude blocks. A 1-degree geographic buffer around held-out blocks excludes nearby training and validation cells. Report the precise held-out block IDs and counts; sensitivity analyses should vary block size and buffer width before making a transfer claim.

## Label definition

The label implementation follows the applicable IMD daily heatwave temperature thresholds at the grid-cell level. It does not implement the station-count and consecutive-day requirements used for official subdivision declarations. The study must say "IMD-aligned grid-cell heatwave day," not an IMD-issued warning.

The target normal is a fixed 1981-2010 Tmax climatology using a centered 15-day circular day-of-year window. A cell's normal is retained only when at least 10 distinct reference years contribute within that smoothing window. Every source file, parameter, access date, API response coordinate, and checksum is recorded in the local acquisition manifests. Raw and derived data remain local; authors should check current source terms before redistribution.
